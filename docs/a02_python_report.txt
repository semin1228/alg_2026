[ 개요 ]

제목이 python: 으로 시작하는 커밋 48개를 순서대로 checkout 해서 직접 입력하고 실행했다.
커밋마다 파일 전체가 다시 돌기 때문에 실행 결과에는 그 커밋에서 새로 나온 출력만 적었다.

환경은 Windows 11, Python 3.13.15 (.venv), pygame 2.6.1, VSCode + Git Graph 다.
소스는 src/w01_python/ 에 있고 최신 커밋에서 src/w02_python/ 으로 이름이 바뀌었다.

캡처가 안 돼서 한 프레임을 그린 다음 pygame.image.save(screen, ...) 로 PNG 를 저장했다.

sorted by y: [(2, 1), (3, 4), (1, 7)]

C 와 비교
여기서 차이가 제일 컸다. C 의 qsort 는 비교 함수에 void* 캐스팅, 음수/0/양수 반환 규칙,
sizeof 전달까지 신경 써야 하고 뺄셈으로 반환하면 오버플로 버그도 생긴다.
Python 은 sorted(edges, key=lambda e: e[2]) 한 줄이다.
그리고 Python 의 sorted 는 안정 정렬이 보장되는데 qsort 는 보장이 없다.

실행 결과
-- two dimensional list --
[0, 0, 0, 0]
[0, 0, 9, 0]
[0, 0, 0, 0]

C 와 비교
C 는 int t[3][4] = {0}; 이고 애초에 행이 독립이라 이 문제의식 자체가 없다.
Python 은 메모리가 연속이 아니라 캐시에 불리한 대신 행마다 길이가 달라도 된다.


47. a03554f  python: 2차원 리스트 aliasing 주의 예제 추가

의도
올바른 방법 바로 뒤에 제일 흔한 오답을 놓아서 대조시킨다.
[[0] * cols] * rows 는 같은 행 리스트를 rows 번 참조한다.

실행 결과
-- two dimensional list aliasing pitfall --
[0, 0, 9, 0]
[0, 0, 9, 0]
[0, 0, 9, 0]

46 과 완전히 같은 대입([1][2] = 9)을 했는데 결과가 이렇게 다르다.

C 와 비교
C 로 흉내 내려면 int *t[3] = {row, row, row}; 처럼 일부러 같은 포인터를 세 번 넣어야 한다.
그렇게 쓰면 누가 봐도 이상한데 [[0]*4]*3 은 너무 자연스러워 보인다. 그게 위험하다.
C 를 먼저 배운 게 오히려 도움이 됐다. 포인터 세 개를 복사한 거구나 로 바로 번역이 됐다.
48개 중에 제일 중요한 커밋 같다. 나머지는 몰라도 코드가 안 돌 뿐인데 이건 코드가
멀쩡히 돌면서 틀린 답을 낸다.

3 4 5.0

8 15 17.0

C 와 비교

10. 총평

강의 구성

커밋 하나가 학습 단위 하나로 짜여 있다. 기본형을 보여주고(10), 문제를 일부러 노출하고(07, 42, 24),
해결하거나 줄이고(08 -> 09 -> 12), 반례로 못 박는(47) 순서가 계속 반복된다.
되는 코드만 보여주는 게 아니라 실패하는 코드를 먼저 보여줘서 왜 그 문법이 있는지가 매번 납득됐다.
그리고 문법 예제인 척하면서 그래프 인접 리스트(13), 간선 가중치 정렬(45), visited set(15),
좌표 변환(36~38) 같은 알고리즘 부품을 미리 만들어 두고 있다.


좋았던 것

다중 반환값(22). C 에서 out-parameter 로 고생하던 게 없어진다.
sorted(key=...)(45). qsort 비교 함수가 한 줄이 된다.
f-string(31). printf 의 인자 개수 불일치 버그가 없어진다.
dictionary 와 set 이 기본으로 있는 것(06, 15). 해시 테이블을 직접 안 짜도 된다.
슬라이싱(04). 분할 정복 코드가 짧아질 것 같다.
import 와 pip(32, 35). 링크 옵션 없이 라이브러리가 쓰인다.
정수 오버플로가 없고 / 가 실수 나눗셈인 것(32, 33).


아쉬운 것

타입 검사가 없다(19, 24, 27). 오타나 잘못된 타입이 실행될 때까지 안 잡힌다.
비용이 코드에 안 보인다. in 이 O(1) 인지 O(n) 인지(08), 슬라이싱이 복사인지(04)가
문법으로는 구분이 안 된다.
참조가 기본이라 생기는 함정(05, 47). 에러 없이 틀린 답이 나온다.
값처럼 보이는데 값이 아닌 것들(01 range, 42 map, 14 keys).
같은 일을 하는 방법이 너무 많다. 포맷팅 세 가지, 변환 네 가지다.


정리

C 는 컴퓨터가 무엇을 하는지를 적는 언어였고 Python 은 내가 무엇을 원하는지를 적는 언어 같다.
알고리즘 수업에는 이게 맞는 것 같다. 알고리즘은 어떤 순서로 무엇을 하느냐가 핵심인데
C 로 쓰면 그게 메모리 관리와 타입 선언에 묻힌다. 대신 상수 배 성능과 컴파일 타임 안전성을
포기한 거라서 위에 적은 아쉬운 점들은 계속 의식해야 할 것 같다.
pygame 부분에서 화면이 한 커밋씩 완성되는 걸 보니 앞으로 정렬이나 그래프를 눈으로 보면서
배우게 된다는 게 실감났다.
